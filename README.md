# SoundSpreader

SoundSpreader 是 VoiceSharer 的 C++/Qt 重构项目，当前发布为纯 Windows 应用：从一个正在播放系统声音的设备进行 WASAPI Loopback 捕获，再把音频分发到多个其他输出设备，也可通过 Windows 蓝牙 A2DP 接收手机媒体音频。

桌面程序使用 HarmonyOS Sans SC 字体，字体版权归 Huawei Device Co., Ltd. 所有，并依照 HarmonyOS Sans Fonts License Agreement 随程序嵌入。完整许可文本位于发行目录的 `licenses/HarmonyOS_Sans_LICENSE.txt`。

## 版本状态

- `v1.0.0`：Qt Widgets 稳定版本，代码位于 `main` 分支并已建立同名 Git 标签。
- `v1.1.0`（已发布）：使用 C#、WinUI 3 和 Windows App SDK 重做桌面界面，代码位于 `feature/winui-v1.1.0` 分支。该版本使用 Mica、Windows 原生控件、系统主题与系统强调色，并针对宽屏和紧凑窗口提供自适应布局。
- `v1.2.72`：VoiceSpreader 与 Android 版本备份标签。
- `v1.3.0`（当前）：发布 SoundSpreader 纯 Windows 版本，保留多设备音频分发和蓝牙 A2DP 接收，隐藏并停用手机网络互联及 VB-CABLE 路由。

WinUI 版本通过 `VoiceSpreader.Native.dll` 复用现有 C++ 音频引擎。目前已接通真实 WASAPI 设备枚举、配置持久化、多输出启停、运行时音量/延迟/同步余量调节、节目电平、声学校准、蓝牙 A2DP 接收、系统托盘和开机自启动。手机互联实现保留在源码中但不会启动，VB-CABLE 不再枚举或关联。Qt Widgets 不再参与新界面，但原生桥接层暂时仍依赖 QtCore 中的基础类型；后续会逐步移除这项运行时依赖。

SoundSpreader 的多设备音频分发按独立输出设备管理，慢设备不会阻塞其他输出；这不是跨设备硬件时钟锁定，在持续长时间播放时仍可能存在轻微漂移。完整本地化和设备热插拔自动恢复仍是已知限制。Windows 原生多设备同步接口的评估和当前算法选择记录在 `docs/WINDOWS_AUDIO_SYNC.md`。

## 当前可用功能

- 枚举 Windows 中所有活动的渲染设备。
- 选择一个主设备作为系统声音捕获源。
- 同时选择多个其他设备作为输出。
- 每个输出设备使用独立的 WASAPI 事件驱动流和环形缓冲。
- 优先尝试 `IAudioClient3` 最小共享周期，不支持时自动回退；独占模式作为高级选项保留。
- 每个输出使用自己的原生混音格式，内置线性重采样，不再依赖 Windows 自动格式转换。
- 自适应重采样会根据缓冲水位细调速率，持续修正独立设备时钟漂移。
- 每个输出设备可设置独立软件音量，运行期间可以实时调整。
- 每个输出设备可设置额外的正向延迟补偿，并可在播放过程中实时平滑调整。
- 同步余量与设备补偿延迟分开配置，默认同步余量为 5 ms，两者都可在播放过程中调整。
- 可以选择一个麦克风进行播放前声学校准：各输出设备按正序和逆序依次播放对数正弦扫频（ESS），程序对麦克风录音做正则化反卷积，保留多组脉冲候选并跨两轮选择位置一致的主峰，同时用对称测量抵消一阶时钟漂移。通过峰值一致性检查后，结果会自动回填到设备补偿。
- 可在播放过程中启用自适应声学跟踪：每台设备分时发送编码探针，优先尝试近超声扫频；检测不到时自动改用低电平扩频探针。
- Windows 可以作为移动设备的蓝牙 A2DP 音箱：顶栏蓝牙按钮会枚举兼容的已配对设备，建立或断开 `AudioPlaybackConnection`，并把移动设备声音播放到 Windows 当前选择的输出设备。
- 连续测量会先积累两轮有效结果，再以每轮最多 2 ms 的速度调整独立“声学自动延迟”；手动补偿仍可实时调节并与其叠加。
- 可根据设备报告的流延迟自动补偿较快的副输出。
- 使用 VoiceSharer 原应用图标；卡片式双栏界面采用 `#112E81`、`#4647AE`、`#4382DF`、`#AACCD6` 品牌配色，并支持独立设计的浅色/深色主题。
- 下拉框、数值微调按钮和音量滑块均使用与品牌配色一致的自绘圆角控件，不再显示 Windows 原生控件外观。
- 可执行文件显式声明 Windows Per-Monitor V2 DPI 感知；窗口在不同 DPI 的显示器之间移动时由 Qt 重新排版和重绘，不再由 Windows 位图拉伸。
- 主内容会根据逻辑宽度在双栏与纵向紧凑布局之间自动切换，并使用外层滚动区域保证 720p 小窗口到 4K 高 DPI 环境都能访问全部控件；底部同步按钮保持固定。
- 同步设置将自动补偿、自同步和独占输出改为带选中态的圆角按钮；输出设备也通过点击设备名称和卡片边框高亮选择，不再使用原生勾选框。
- 自同步无需先执行手动校准：每个输出获得两轮可信探针后会直接建立初始相对延迟基准，随后才切换为每轮最多 2 ms 的漂移跟踪；初始基准尚未完成时保持较高测量频率。
- 支持真正的系统托盘后台运行：点击底部“最小化到托盘”或直接关闭主窗口都不会中断同步或蓝牙连接；托盘菜单可恢复窗口或彻底退出。
- 底部“开机自启动”使用 MSIX 原生 StartupTask，不需要管理员权限；登录后会以隐藏主窗口的方式直接进入托盘。直接运行未打包程序时自动回退到当前用户启动项。
- 内嵌 HarmonyOS Sans SC 常规、中黑与粗体字重，并启用 Qt 高 DPI 与高分辨率图标支持，改善 Windows 缩放下的文字和图标清晰度。
- 主设备不会出现在输出列表中，避免程序捕获自己的输出而形成反馈。

当前版本尚未包含：

- 自研虚拟音频驱动。
- 设备热插拔自动恢复。

由于选择物理来源时，来源设备仍由 Windows 直接播放，SoundSpreader 只能延迟其他输出，不能让慢设备提前。如果蓝牙等设备明显最慢，应优先将其选作捕获源，再给较快设备增加额外延迟。

SoundSpreader 不依赖 VB-CABLE 或其他第三方虚拟音频端点；选择实体设备作为来源和输出即可完成多设备分发。

## 使用方法

1. 在 Windows 声音设置中，将准备作为主设备的扬声器或耳机设为默认输出。
2. 运行 SoundSpreader。
3. 在“音频来源”中选择该主设备。
4. 点击一个或多个其他输出设备的名称；卡片出现蓝色边框即表示已选择。
5. 如需自动对齐，在“校准麦克风”选择能听到所有扬声器的麦克风，把它放在实际听音位置，至少选择两个输出并点击“自动校准”。测试会依次播放正反序 ESS 扫频，完成后自动写入各设备的“实时补偿”，并关闭会重复计算同一路径的端点“自动补偿”。
6. 默认保持“独占输出”关闭。只有多个输出属于互相独立的物理声卡时才建议尝试；同一驱动暴露的多个端点可能互斥。
7. 如需长时间抑制设备漂移，保持“自同步”开启。麦克风位置应与播放前校准时一致。
8. 如需接收手机系统媒体声音，点击顶栏蓝牙按钮；尚未完成系统蓝牙配对时选择“配对新设备”，配对后刷新并点击“连接并接收声音”。
9. 点击“开始同步”。需要隐藏界面时点击“最小化到托盘”，或直接关闭主窗口；点击托盘图标可恢复窗口，选择托盘菜单中的“退出”才会彻底结束程序。
10. 如需随 Windows 登录自动运行，点击底部“开机自启动”；按钮变为选中状态即表示已启用，再次点击可关闭。

日志会显示每台设备最终使用“独占低延迟”“共享低延迟”还是“兼容模式”，并显示周期、流延迟、采样率转换与停止时的时钟修正统计。

播放过程中可以直接修改已选设备的“实时补偿”。程序会短暂调整该设备的重采样速率来追踪新的缓冲目标；较大的延迟变化可能带来短暂、轻微的音高变化，稳定后会自动恢复正常速率。

自动校准测到的是“程序输出 → 设备/驱动 → 扬声器 → 空气传播 → 麦克风”的整体到达时间。因为所有设备在同一轮录音中使用同一个麦克风，麦克风自身延迟会作为公共项抵消；扬声器到麦克风的距离差则会被有意包含，因此校准只对当时的听音位置最准确。没有接扬声器的端点、蓝牙设备的通话模式、系统降噪/回声消除和过低音量都可能降低置信度。

当前播放中同步分为三层：缓冲水位控制负责短期连续性和设备时钟速率差；设备报告的流延迟提供初始补偿；麦克风通过逐设备编码探针间歇复核真实的“驱动—扬声器—空气”路径。探针直接混入现有输出流，不另开播放端点。测量采用最近三次结果的中位数，并在至少连续两轮有效后才缓慢修改声学自动延迟，避免反射或瞬时噪声造成跳变。

近超声探针工作在大约 20.4–22 kHz，超声幅度限制在 0.0012–0.006（约 −58 至 −44 dBFS）；超声连续失败时会切换到约 15–15.8 kHz 载波、幅度约 −64 至 −50 dBFS 的低电平扩频序列。检测端会先做探针频带的 FIR 带通再相关，以较少的发送能量换取检测能力。所有探针都受实时多声道 RMS 硬门控：节目电平低于约 −44 dBFS 时不会启动，发送过程中变为静音也会立即截断。界面会显示实时节目电平、是否允许探针，以及每台设备的探针模式、声学自动延迟、相对漂移估计和相关置信度。

高频探针对多数成年人不明显，但不能保证对所有人和动物完全不可闻；某些扬声器或采样率转换还可能通过非线性失真产生更低的可闻分量。因此“节目声硬门控”是必要的第二道保护，而不是只依赖名义载频。

SoundSpreader 不启动手机配对服务器、不读取 Android 互联会话，也不枚举或写入 VB-CABLE；Android 工程作为独立的 VoiceSpreader 版本保留在 `VoiceSpreaderAndroid` 仓库中。

## 本机构建

### WinUI 3（v1.3.0）

除下方 C++ 工具链外，还需要 .NET 9 SDK。执行以下命令会先构建原生桥接库，再构建并启动 WinUI 应用：

```powershell
.\build-winui.ps1 -Configuration Debug -Run
```

仅构建 Release 版本：

```powershell
.\build-winui.ps1 -Configuration Release
```

Release 产物位于 `src\VoiceSpreader.App\bin\Release\net9.0-windows10.0.26100.0\win-x64\`。应用以非打包、自包含的 WinUI 3 桌面程序运行，目录中会同时部署原生桥接库及其当前所需的 QtCore 运行库。

验证手机配对、PCM 和远程时钟协议：

```powershell
dotnet run --project tests\VoiceSpreader.App.Smoke\VoiceSpreader.App.Smoke.csproj -c Debug
```

### Qt Widgets（v1.0.0）

当前构建脚本默认使用：

- Qt 5.15.2：`D:\Anaconda\Library`
- Visual Studio 2022 C++ 工具链
- CMake + Ninja
- Windows 10/11 SDK

在 PowerShell 中执行：

```powershell
.\build.ps1
```

如果默认打包目录中的旧程序仍在运行，可临时输出到其他目录：

```powershell
.\build.ps1 -PackageDir 'dist\VoiceSpreader-next'
```

构建成功后：

- 原始程序：`build\VoiceSpreader.exe`
- 带 Qt 运行库的目录：`dist\VoiceSpreader\VoiceSpreader.exe`
