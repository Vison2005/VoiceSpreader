# VoiceSpreader

VoiceSpreader 是 VoiceSharer 的 C++/Qt 重构项目。当前阶段先实现不依赖 VoiceMeeter 的纯用户态版本：从一个正在播放系统声音的设备进行 WASAPI Loopback 捕获，再把音频分发到多个其他输出设备。

## 当前可用功能

- 枚举 Windows 中所有活动的渲染设备。
- 选择一个主设备作为系统声音捕获源。
- 同时选择多个其他设备作为输出。
- 每个输出设备使用独立的 WASAPI 事件驱动流和环形缓冲。
- 优先尝试 `IAudioClient3` 最小共享周期，不支持时自动回退；独占模式作为高级选项保留。
- 每个输出使用自己的原生混音格式，内置线性重采样，不再依赖 Windows 自动格式转换。
- 自适应重采样会根据缓冲水位细调速率，持续修正独立设备时钟漂移。
- 每个输出设备可设置独立软件音量，运行期间可以实时调整。
- 每个输出设备可设置额外的正向延迟补偿，并可在播放过程中实时平滑调整。
- 同步余量与设备补偿延迟分开配置，默认同步余量为 5 ms，两者都可在播放过程中调整。
- 可以选择一个麦克风进行播放前声学校准：程序让每台输出依次播放三次宽带扫频，使用归一化互相关估计到达时间，中位数结果会自动回填到设备补偿。
- 可在播放过程中启用自适应声学跟踪：每台设备分时发送编码探针，优先尝试近超声扫频；检测不到时自动改用低电平扩频探针。
- Android 手机可作为远程声学校准位置麦克风：支持二维码或六位码局域网配对，连续回传带绝对采样帧号的 48 kHz PCM16。
- 连续测量会先积累两轮有效结果，再以每轮最多 2 ms 的速度调整独立“声学自动延迟”；手动补偿仍可实时调节并与其叠加。
- 可根据设备报告的流延迟自动补偿较快的副输出。
- 卡片式双栏界面，并支持浅色/深色主题。
- 主设备不会出现在输出列表中，避免程序捕获自己的输出而形成反馈。

当前版本尚未包含：

- 自研虚拟音频驱动。
- 设备热插拔自动恢复。

由于选择物理来源时，来源设备仍由 Windows 直接播放，VoiceSpreader 只能延迟其他输出，不能让慢设备提前。如果蓝牙等设备明显最慢，应优先将其选作捕获源，再给较快设备增加额外延迟。

如果机器上已有虚拟音频端点，可以暂时将 Windows 默认输出指向该虚拟端点，再在 VoiceSpreader 中把它选作来源，并把所有实体设备选作输出。这样不会有一个实体设备绕过 VoiceSpreader 直接发声，设备间更容易精确对齐。彻底不依赖第三方虚拟端点仍需要后续自研驱动。

## 使用方法

1. 在 Windows 声音设置中，将准备作为主设备的扬声器或耳机设为默认输出。
2. 运行 VoiceSpreader。
3. 在“系统声音捕获源”中选择该主设备。
4. 勾选一个或多个其他输出设备。
5. 如需自动对齐，在“声学校准麦克风”选择能听到所有扬声器的麦克风，把它放在实际听音位置，至少勾选两个输出并点击“自动校准”。测试会依次播放短扫频，完成后自动写入各设备的“实时补偿”。
6. 默认保持“实验性：优先独占输出”关闭。只有多个输出属于互相独立的物理声卡时才建议尝试；同一驱动暴露的多个端点可能互斥。
7. 如需长时间抑制设备漂移，保持“播放中自适应声学跟踪”开启。麦克风位置应与播放前校准时一致。
8. 如果使用手机麦克风，点击“配对手机”，在 Android 应用扫描二维码或输入六位码；配对后勾选“连续声学跟踪使用手机麦克风”。
9. 点击“开始同步”。

日志会显示每台设备最终使用“独占低延迟”“共享低延迟”还是“兼容模式”，并显示周期、流延迟、采样率转换与停止时的时钟修正统计。

播放过程中可以直接修改已选设备的“实时补偿”。程序会短暂调整该设备的重采样速率来追踪新的缓冲目标；较大的延迟变化可能带来短暂、轻微的音高变化，稳定后会自动恢复正常速率。

自动校准测到的是“程序输出 → 设备/驱动 → 扬声器 → 空气传播 → 麦克风”的整体到达时间。因为所有设备在同一轮录音中使用同一个麦克风，麦克风自身延迟会作为公共项抵消；扬声器到麦克风的距离差则会被有意包含，因此校准只对当时的听音位置最准确。没有接扬声器的端点、蓝牙设备的通话模式、系统降噪/回声消除和过低音量都可能降低置信度。

当前播放中同步分为三层：缓冲水位控制负责短期连续性和设备时钟速率差；设备报告的流延迟提供初始补偿；麦克风通过逐设备编码探针间歇复核真实的“驱动—扬声器—空气”路径。探针直接混入现有输出流，不另开播放端点。测量采用最近三次结果的中位数，并在至少连续两轮有效后才缓慢修改声学自动延迟，避免反射或瞬时噪声造成跳变。

近超声探针工作在大约 20.4–22 kHz，超声幅度限制在 0.0012–0.006（约 −58 至 −44 dBFS）；超声连续失败时会切换到约 15–15.8 kHz 载波、幅度约 −64 至 −50 dBFS 的低电平扩频序列。检测端会先做探针频带的 FIR 带通再相关，以较少的发送能量换取检测能力。所有探针都受实时多声道 RMS 硬门控：节目电平低于约 −44 dBFS 时不会启动，发送过程中变为静音也会立即截断。界面会显示实时节目电平、是否允许探针，以及每台设备的探针模式、声学自动延迟、相对漂移估计和相关置信度。

高频探针对多数成年人不明显，但不能保证对所有人和动物完全不可闻；某些扬声器或采样率转换还可能通过非线性失真产生更低的可闻分量。因此“节目声硬门控”是必要的第二道保护，而不是只依赖名义载频。

手机端不会把网络包抵达电脑的时刻当成声学到达时刻，而是给每块录音附上从 `AudioRecord` 启动后连续递增的采样帧号。设备之间作差时，手机录音时钟和电脑 QPC 的固定原点偏移、相同路径上的网络传输等待都会消失；剩余误差主要来自手机采样时钟与电脑时钟的微小速率差、丢失采样和声学检测误差。TCP 用于保证数据有序且不丢帧，因此网络抖动只要没有耗尽 30 秒接收缓冲，就不会直接变成测得的设备延迟。

当前手机音频协议只做临时会话密钥校验，没有加密，适合个人在可信家庭局域网内使用。Android 工程位于同级目录 `VoiceSpreaderAndroid`。

如果电脑同时启用有线、Wi-Fi、VPN 或虚拟机网卡，配对窗口会列出全部可用 IPv4 地址并默认优先实体有线网卡。二维码直连失败时，Android 端还会用二维码中的随机会话 ID 广播定位电脑，并采用 UDP 回包的实际源地址重连。桥接网络中仍可在“二维码电脑地址”手动选择与手机同一局域网的地址；例如本机有线地址为 `192.168.3.133` 时，应选择它而不是默认网关 `192.168.3.1`。

## 本机构建

当前构建脚本默认使用：

- Qt 5.15.2：`D:\Anaconda\Library`
- Visual Studio 2022 C++ 工具链
- CMake + Ninja
- Windows 10/11 SDK

在 PowerShell 中执行：

```powershell
.\build.ps1
```

如果默认打包目录中的旧程序仍在运行，可临时输出到其他目录：

```powershell
.\build.ps1 -PackageDir 'dist\VoiceSpreader-next'
```

构建成功后：

- 原始程序：`build\VoiceSpreader.exe`
- 带 Qt 运行库的目录：`dist\VoiceSpreader\VoiceSpreader.exe`
