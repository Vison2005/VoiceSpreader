# 傅里叶域音频同步：论文中的数学方法与工程实现

## 1. 研究结论

查阅的论文表明，傅里叶方法已经能够在工程上解决“相对同步”问题，但要区分四种不同未知量：

| 未知量 | 傅里叶域是否可估计 | 常用方法 | 最终补偿 |
|---|---|---|---|
| 初始采样时间偏移 STO | 可以，前提是两路含有共同音频 | 互谱相位斜率、GCC-PHAT、频域相关峰 | 整数延迟 + 分数延迟 |
| 采样率偏移 SRO | 可以，前提是共同音频在一段时间内保持可观测 | STFT 线性相位漂移、相干性漂移、相关最大化、DXCP | ASRC、重采样或时变分数延迟 |
| 逐渐累积的整采样漂移 FSD/FFD | 可以检测，但单纯相位旋转不够 | 样本计数、帧边界检测、WOLA 状态管理 | 跳过/复制样本或帧，再做频域相位校正 |
| 声卡、蓝牙、DAC 的固定端到端延迟 | 仅靠 FFT 无法直接观察 | 回环、声学测量、设备标定、硬件时钟 | 固定延迟表、预缓冲、播放时间线补偿 |

因此，傅里叶变换不是“直接让 Windows 多个设备同时发声”的单一开关，而是同步闭环中的**观测器和分数校正器**。论文里真正可落地的结构通常是：

~~~text
共同音频
  → STFT/FFT 互谱
  → STO/SRO 估计
  → 整数样本与分数相位补偿
  → ASRC/PLL 慢速跟踪
  → 继续观测并记录置信度
~~~

## 2. 最有工程价值的论文

### 2.1 Didier 等：相干性漂移 + 频域相位补偿

论文：[Sampling Rate Offset Estimation and Compensation for Distributed Adaptive Node-Specific Signal Estimation in Wireless Acoustic Sensor Networks](https://doi.org/10.1109/ojsp.2023.3243851)；[开放版 PDF](https://ftp.esat.kuleuven.be/pub/stadius/pdidier/icassp2023/didier2023a_published.pdf)。

这篇论文最接近“从已有音频直接估计并补偿时钟漂移”的完整工程方案：

1. 每个节点对音频做 WOLA/STFT；
2. 计算两路 STFT 的互功率谱和归一化相干性；
3. 比较相隔 \(l_d\) 帧的相干性相位；
4. 由频率维度相位斜率估计平均 SRO；
5. 将累计漂移换算为分数样本延迟，并在 STFT 域乘以相位旋转；
6. 额外检测一个样本或一个 WOLA 帧的 full-sample/full-frame drift。

其关键关系可以写成：

\[
\angle\left\{\Gamma_{kq}[\nu,i]\Gamma_{kq}^{*}[\nu,i-l_d]\right\}
\approx
\frac{2\pi}{N}\nu l_d N_s\hat{\epsilon}_{kq}[i],
\]

其中 \(N\) 为 DFT 长度，\(\nu\) 为频率 bin，\(N_s\) 为帧移，\(\hat{\epsilon}\) 为 SRO 估计。论文指出，\(l_d\) 越大，平均时间越长、估计更稳健，但越难跟踪时变 SRO。对相位直接做最小二乘会受到 \(2\pi\) 周期影响，因此论文还把相干性乘积视作广义互谱，通过逆 DFT 找相关峰，再用非整数峰值插值提高精度。

分数漂移校正为：

\[
\tilde z_q[\nu,i]
=z_q[\nu,i]\exp\left(j\frac{2\pi}{N}\nu\hat{\tau}_{kq}[i]\right),
\quad
\hat{\tau}_{kq}[i]
=N_s\sum_{\iota=0}^{i}\hat{\epsilon}_{kq}[\iota].
\]

这不是只给出理论公式：论文还处理了 WOLA 里“累计一个整采样后只靠相位旋转无法恢复”的问题。它通过逐样本传输和 WOLA 失真函数的时域卷积近似来检测和补偿 full-sample drift；代价是增加计算和通信设计复杂度。

**可迁移到 Windows 的内容：**

- 分析线程使用 FFT，输出 \(\hat{\tau}\)、\(\hat{\epsilon}\) 和置信度；
- 播放线程用分数延迟滤波器/ASRC 应用校正；
- 当累计漂移接近一个采样点时，必须维护样本计数和帧边界；
- 不应把“每帧乘一次相位”误认为可以处理所有长期漂移。

### 2.2 Wang 与 Doclo：相关最大化 SRO 搜索

论文：[Correlation Maximization Based Sampling Rate Offset Estimation for Distributed Microphone Arrays](https://doi.org/10.1109/TASLP.2016.2517326)；[论文摘要和全文页面](https://www.researchgate.net/publication/290509788_Correlation_Maximization_Based_Sampling_Rate_Offset_Estimation_for_Distributed_Microphone_Arrays)。

该方法把“相位漂移模型”直接变成可实现的搜索算法：

1. 假设一个候选 SRO \(\epsilon_c\)；
2. 在 STFT 域用线性相位模型补偿一路信号；
3. 对补偿后的两路信号计算相关系数；
4. 选择使相关系数最大的 \(\epsilon_c\)；
5. 用粗搜索 + 细搜索降低计算量和线性相位近似误差。

\[
\hat{\epsilon}
=\arg\max_{\epsilon_c\in\mathcal{E}}
\operatorname{corr}\left(
x(t),\,\mathcal{C}_{\epsilon_c}\{y(t)\}
\right).
\]

论文明确指出：当 SRO 或处理信号长度变大时，单纯 STFT 线性相位漂移模型会失真，所以采用 two-stage exhaustive search。该思路的优点是目标函数直观、容易离线验证；缺点是搜索成本随候选范围和步长增长，不适合作为每个音频回调都执行的控制器。适合放在初始化、低频率再校准或后台分析线程。

### 2.3 Schmalenstroeer 与 Haeb-Umbach：FFT/Overlap-Save 重采样

论文：[Efficient Sampling Rate Offset Compensation](https://groups.uni-paderborn.de/nt/pubs/2018/Eusipco_2018_Schmalenstroeer_Paper.pdf)。

这篇 EUSIPCO 论文重点不是估计 SRO，而是把理论上的高精度 sinc 重采样变成可流式运行的频域工程实现：

- 整数采样偏移由输入 buffer 的 shift/读指针处理；
- 分数采样相位由 FFT 后乘以指数相位因子处理；
- IFFT 后使用 overlap-add；
- 另一条路径使用 Overlap-Save，把理想 sinc 重构近似成线性卷积。

STFT 近似模型为：

\[
X_R[l,k]\approx X_S[l,k]
\exp\left(
-j\frac{2\pi}{N}
\left(\frac{B}{2}+lB\right)k\epsilon
\right),
\]

其中 \(B\) 是 block shift，\(N\) 是 FFT 长度。实际算法使用 Hann 窗、半块重叠，并把整数部分交给 buffer，分数部分交给频域相位旋转。

论文的工程结论很具体：

- 名义采样率 16 kHz、人工生成宽带伪随机信号，测试 SRO 为 50、100、160 ppm；
- STFT 方法在 \(B=512,N=1024\) 附近取得较好的精度与复杂度折中；
- Overlap-Save 在宽带、小 SRO 情况下接近长窗 sinc 的质量，但速度约为 sinc 插值的 4 倍；
- 当要求 SRO 约 50 ppm 且 SINR 大于 60 dB 时，论文给出的一个 OSM 参数例子是 \(B=32,N=1024\)，处理时间约为每秒音频 0.08 秒；
- FFT 不能无限增大：窗口变长会增加延迟，也会让“一个固定相位斜率描述整帧”的近似变差。

这篇论文对 Windows 最有用的地方是给出了“如何把公式变成实时块处理”的答案，而不是只说“使用 ASRC”。

### 2.4 Chinaev 等：DXCP + ASRC 闭环控制

论文：[Control Architecture of the Double-Cross-Correlation Processor for Sampling-Rate-Offset Estimation in Acoustic Sensor Networks](https://www.2021.ieeeicassp.org/2021.ieeeicassp.org/Papers/ViewPaper235d.html)；[在线双重互相关论文](https://arxiv.org/abs/2105.13743)。

该工作解决的是一个实际问题：先估计一次 SRO、再执行一次 ASRC，通常会留下残差；残差经过长时间播放又会积累。论文把离线多阶段流程改成连续反馈控制：

\[
\text{audio frame}
\rightarrow
\text{controlled ASRC}
\rightarrow
\text{online DXCP}
\rightarrow
\text{SRO error}
\rightarrow
\text{controller update}.
\]

论文摘要明确说明：

- SRO 与离散时间信号之间是非线性关系；
- DXCP 能在线估计，但存在偏差；
- 只做一次 ASRC 会留下不可接受的残差；
- 通过 ASRC 控制单元和在线 DXCP 组成闭环，可以每个信号帧只处理一次，同时逐渐压低 SRO 偏差；
- 论文用语音和高斯输入验证了低复杂度单级处理仍可接近多级离线处理的精度。

对 Windows 播放器而言，这对应一个低带宽控制回路：FFT/DXCP 估计线程不直接重写音频数据，而是只更新 ASRC 的微小比率偏置，例如 \(1+\hat{\epsilon}\)；控制器需要限幅、积分防饱和和置信度门控。

### 2.5 Sanchez-Bote 与 Gomez-Alfageme：频域分数延迟

论文：[Fractional Delay in the Frequency Domain for Beamforming Applications](https://secure.aes.org/forum/pubs/journal/?elib=15248)。

这篇 JAES 论文专门讨论麦克风阵列和扬声器阵列中的实时分数延迟。其工程核心是：对短时频谱乘以与延迟成正比的相位因子，在 IFFT 后即可得到分数延迟的音频块。论文还讨论窗函数、频率变换和时间对齐误差对波束形成精度的影响。

它适合作为 VoiceSpreader 的“亚采样延迟执行器”参考，但不应单独承担 SRO 估计。频域相位旋转可以实现当前延迟的微调，却不能替代长期采样率控制。

## 3. 数学模型：从观测到补偿

### 3.1 STO：互谱相位斜率

若 \(y[n]=x[n-\tau]\)，则：

\[
Y[k]=X[k]\exp\left(-j\frac{2\pi k}{N}\tau\right).
\]

令 \(C[k]=Y[k]X^*[k]\)，对 \(\angle C[k]\) 展开并做加权线性回归：

\[
\hat{\tau}
=-\frac{N}{2\pi}
\frac{\sum_k w_k(k-\bar{k})(\phi_k-\bar{\phi})}
{\sum_k w_k(k-\bar{k})^2}.
\]

权重 \(w_k\) 应同时考虑能量和相干性；静音频点、强噪声频点和相位不稳定频点不要参与拟合。

### 3.2 SRO：相对延迟随时间变化

以参考采样时钟 \(T_r\) 为基准，另一设备满足：

\[
T_\epsilon=T_r(1+\epsilon),\qquad
\tau(t)\approx \tau_0+\epsilon f_s t.
\]

因此，SRO 的本质是 STO 的时间斜率：

\[
\epsilon\approx
\frac{\tau(t_2)-\tau(t_1)}
{f_s(t_2-t_1)}.
\]

STFT 的 LPD 模型把这个关系变为二维相位平面：

\[
Y[k,l]\approx X[k,l]
\exp\left(j\frac{2\pi k}{N}\tau[l]\right).
\]

频率方向的斜率估计当前延迟，帧方向的斜率估计 SRO。

### 3.3 分数延迟执行

拆分：

\[
\hat{\tau}=\hat{\tau}_{\mathrm{int}}
+\hat{\tau}_{\mathrm{frac}},
\qquad
\hat{\tau}_{\mathrm{int}}=\operatorname{round}(\hat{\tau}).
\]

整数部分由 ring buffer 读指针或样本插入/丢弃处理；分数部分：

\[
Z_{\mathrm{corr}}[k,l]
=Z[k,l]\exp\left(
-j\frac{2\pi k}{N}\hat{\tau}_{\mathrm{frac}}
\right).
\]

相位旋转的符号取决于“提前”还是“延后”的定义，必须用单次已知延迟测试确认。

### 3.4 ASRC/PLL 闭环

将 SRO 转成重采样比：

\[
\rho=\frac{1}{1+\hat{\epsilon}}.
\]

以延迟误差 \(e_l=\hat{\tau}_l-\tau^*\) 为反馈，可采用：

\[
u_l=K_p e_l+K_i\sum_{q=0}^{l}e_q,
\qquad
\rho_l=\rho_0+\operatorname{clip}(u_l).
\]

控制器的目标不是让每个 FFT 帧的 \(\hat{\tau}\) 都为零，而是让延迟缓慢回到目标缓冲位置，避免音高抖动、频繁丢样本和 buffer underflow。

## 4. 论文方法的工程可实现性对比

| 方法 | 估计输入 | 计算位置 | 可否在线 | 主要优点 | 主要风险 |
|---|---|---|---|---|---|
| GCC-PHAT/互谱峰 | 共同宽带音频 | FFT 分析线程 | 可以 | STO 直观、延迟估计精度高 | 混响、多峰、无共同源时失效 |
| 相位斜率 LS | 共同音频 STFT | 分析线程 | 可以 | 分数采样精度、公式简单 | 相位展开和低相干频点 |
| 相干性漂移 | 共同音频、较长观测 | 分析线程 | 可以 | 盲 SRO、适合网络设备 | 需要累计帧，时变 SRO 有滞后 |
| 相关最大化 | 共同音频 + 候选 SRO 网格 | 后台/初始化 | 可但成本较高 | 目标函数直观、容易验证 | 搜索复杂度和模型误差 |
| DXCP + ASRC | 共同音频帧 | 分析 + 控制线程 | 可以 | 闭环、能压低长期残差 | 控制器调参和估计偏差 |
| STFT/OSM 重采样 | 已知 SRO 或时变延迟 | 音频处理线程 | 可以 | 分数延迟、块处理高效 | FFT 延迟、窗口近似误差 |
| Farrow（时域） | 共同带限信号 | 音频处理线程 | 可以 | 与补偿器共用结构、无 FFT | 插值阶数和带宽决定失真 |

## 5. 对 Windows 的具体工程方案

### 5.1 线程分工

1. **采集/播放线程**：WASAPI 事件驱动，使用 IAudioClock 读取设备内硬件位置；回调里只搬运 buffer。
2. **FFT 分析线程**：按 \(N\) 点窗、\(H\) 点 hop 计算 STFT、互谱、相干性和置信度。
3. **同步估计线程**：维护 \(\hat{\tau}\)、\(\hat{\epsilon}\)、相位展开状态、相关峰和拟合残差。
4. **校正线程**：用整数读指针、分数延迟或 ASRC 修改即将播放的样本；使用原子变量或无锁消息传递接收控制参数。
5. **监控线程**：记录 QPC 时间、IAudioClock 位置、buffer 深度、SRO、校正比率、underflow/overflow 和估计置信度。

QPC 适合统一软件事件时间戳，IAudioClock 适合设备内部帧位置；二者不能互相替代。Windows 的 MMCSS 和低延迟模式可以降低调度抖动，但不能使两个独立声卡共享一个采样振荡器。

### 5.2 推荐的三级同步环

**第一级：粗同步**

- 用短时能量、频谱流或 GCC-PHAT 找到毫秒级候选偏移；
- 将偏移写入每路 ring buffer 的初始读指针；
- 只在置信度足够高时执行大步调整。

**第二级：精同步**

- 对最近若干 STFT 帧做互谱相位斜率；
- 只对高相干频带加权；
- 用分数相位旋转消除亚采样误差。

**第三级：长期同步**

- 用相干性漂移、相关最大化或 DXCP 估计 ppm 级 SRO；
- 通过 ASRC/PLL 缓慢改变播放速率；
- 维护 FSD/FFD 计数，必要时在静音或低能量窗口执行样本/帧修正。

### 5.3 参数起点

以 48 kHz 为例：

| 目标 | FFT 长度 \(N\) | hop \(H\) | 说明 |
|---|---:|---:|---|
| 语音快速粗同步 | 1024 | 256 | 21.3 ms 窗口，约 5.3 ms 更新 |
| 音乐精同步 | 2048–4096 | \(N/4\) | 相位斜率更稳，但延迟更高 |
| 分数延迟/ASRC | 512–1024 | \(N/4\) 或更小 | 需关注窗口近似误差 |
| 相关最大化后台搜索 | 2048–4096 | \(N/2\) | 不放在实时回调中 |

使用 Hann 窗和 50%–75% 重叠；对 50–8000 Hz 或设备有效带宽做掩码。所有参数都应通过真实声卡和目标 CPU 做 SINR、延迟和失锁率测试。

### 5.4 实时伪代码

~~~text
每个 STFT 帧 l:
    Xa = FFT(hann(a[l:l+N]))
    Xb = FFT(hann(b[l:l+N]))
    C  = Xa * conj(Xb)
    coh = abs(C)^2 / (Saa * Sbb + delta)

    tau_l = weighted_phase_slope(
        unwrap(angle(C)), weight=coh
    )
    epsilon_l = robust_slope(history_of_tau)

    tau_int  = round(tau_l)
    tau_frac = tau_l - tau_int
    ring_buffer.shift(tau_int)
    stft_phase_rotate(-2*pi*k*tau_frac/N)

    rho = clamp(1/(1+epsilon_l), rho_min, rho_max)
    asrc.set_ratio(low_pass_filter(rho))

    log(tau_l, epsilon_l, coh, residual, buffer_level)
~~~

不要在低置信度时强行更新 ASRC。静音、窄带纯音、严重混响或两个设备播放不同内容时，应冻结校正并等待重新锁定。

## 6. 不能由这些论文直接解决的部分

### 6.1 固定设备延迟

FFT 只能看到共同音频到达分析点的相对关系。Windows 音频引擎缓冲、声卡 DAC 群时延、蓝牙编码/解码和扬声器到麦克风的空气传播延迟，若不出现在共同观测路径中，就无法从互谱中分离出来。

工程上要先做每设备端到端回环标定，建立：

\[
D_i=D_{i,\mathrm{WASAPI}}
+D_{i,\mathrm{driver}}
+D_{i,\mathrm{DAC}}
+D_{i,\mathrm{Bluetooth}}
+D_{i,\mathrm{air}}.
\]

### 6.2 没有共同源

两个设备播放完全不相关的音频时，互谱相位没有可解释的同步关系。此时必须共享数字音频、共享网络时间戳、使用声学探针/回环，或先设计可匹配的音频指纹。

### 6.3 采样调度抖动

Windows 线程可能被抢占。FFT 能估计“已经录到的音频”之间的偏移，但不能保证回调在某个绝对时刻运行。实际输出仍要依靠预缓冲、事件驱动 WASAPI、MMCSS 和 underflow 保护。

## 7. 对 VoiceSpreader 的建议

推荐实现顺序：

1. 先用 IAudioClock、QPC 和 WASAPI buffer level 建立每个设备的播放时间线；
2. 通过一次端到端回环标定固定延迟；
3. 用 GCC-PHAT 或互谱相位斜率做初始 STO；
4. 用 STFT 相干性漂移估计长期 SRO；
5. 用“整数读指针 + 频域分数延迟 + 慢速 ASRC”完成三级补偿；
6. 记录 \(\hat{\tau}\)、\(\hat{\epsilon}\)、相干性、相关峰比、拟合残差、ASRC 比率和听感失锁事件；
7. 若 FFT 线程占用过高，再评估 Farrow/多相 FIR 方案，把同一插值器同时用于估计和补偿。

验收指标建议至少包括：

- 起始 STO 的均值、95% 分位数；
- 10 分钟和 1 小时的最大相对漂移；
- SRO 估计 RMSE（ppm）；
- ASRC 引入的 SINR/THD+N/音高变化；
- underflow/overflow 次数；
- 混响、静音、窄带、蓝牙和不同采样率组合下的失锁率。
