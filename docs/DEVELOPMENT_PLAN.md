# VoiceSpreader 总体开发计划

## 当前基线

- `v1.2.4.2`：回归最小稳定版，只启用全屏触摸板；v1.2.4.1 及更早版本代码和安装包继续归档。
- `v1.2.4.3`：修复触摸板连接可靠性，主题跟随应用明暗模式，并完善 protocol 2 音频会话上的输入帧兼容与 SendInput 诊断。
- `v1.2.4.6`：触摸板纯色全屏界面、异形屏安全区设置面板，以及双指捏合缩放（Ctrl+滚轮）协议。
- `v1.2.4.7`：精简触摸板设置入口，仅保留光标速度；增加滚动/捏合手势锁定与更低灵敏度，修复同水平线或同垂直线双指滚动判定。
- `v1.2.4.71`：补发高刷新率屏幕的触摸历史采样，降低单指光标卡顿；收紧竖屏设置入口的顶部安全间距。
- `v1.2.4.72`：修复 MSIX 安装包升级后开机自启动失效，改用 Windows 原生 StartupTask 并迁移旧注册表启动项。
- `v1.2.4.8`：新增三指/四指触摸板滑动、点按和双击映射，支持鼠标动作、电脑端应用和自定义 Windows 组合键。
- `v1.2.4.8`（规划）：Touch Bar 常驻信息与控制面板。
- `v1.2.4.9`（规划）：Android 平板压感笔数位板模式。
- 现有配对会话使用会话 ID 与 secret 认证；控制/音频帧使用 4 字节大端长度 + 1 字节类型的二进制帧。
- 新功能必须保持旧版 `protocol=2` 的兼容性；支持新功能的双方使用 `protocol=3`。
- protocol 3 的功能控制连接可与 protocol 2 音频连接并行；Windows 按 `deviceId` 分别维护音频会话与功能会话，不能互相覆盖。

## v1.2.4.2：最小稳定触摸板

- Android 端只声明 `input.touchpad` 能力，暂时隐藏快捷键、文件、扫码、拍照和应用目录入口。
- 触摸板页面改为纯黑全屏输入面，不再在触摸事件期间重建主题、工具栏或分屏面板。
- 单指移动/单击、双指滚动复用已经认证的音频 TCP 连接；发送单帧失败只丢弃该帧，不主动销毁会话。
- Windows 与 Android 保留旧版功能源码和 v1.2.4.1 发布物，归档目录不参与当前构建。

## v1.2.4.1：稳定性补丁

- 手机主动停止麦克风时，Windows 只收敛本地状态，不再重复回发停止命令。
- 触摸板、鼠标按键、滚动和快捷键事件与 TCP 生命周期隔离；本机输入注入失败不会关闭功能通道。
- Android 与 Windows 统一版本号，保留 protocol 2 音频兼容和 protocol 3 功能通道回归测试。

## v1.2.4.0：手机控制与内容投送

### 功能目标

将手机变成 Windows 的局域网控制面板和内容投送入口：

1. 全屏触摸板与多指手势。
2. 纯黑的“极暗主题”，只改变应用颜色，不修改系统亮度。
3. 触摸板底栏/侧栏快捷键，多页面与有限组合动作。
4. 触摸板内嵌文件管理器分屏：文件可拖入触摸板共享区自动发送。
5. 电脑端可配置应用白名单，手机触摸板同步显示一键启动入口。
6. 照片、视频、文档高速投送；1.2.4.0 先完成手机→Windows，使用独立文件数据连接，双向协议预留。
7. 手机拍照后直接发送到 Windows；录像传输作为实验能力。
8. 手机摄像头扫码、相册图片扫码、电脑请求扫码、手机主动扫码。
9. URL 安全确认后使用 Windows 默认浏览器打开。

### 分阶段实现

#### 阶段 A：协议与安全边界

- 将 hello 扩展为协议 3 和 capabilities 协商。
- 保留现有音频帧类型和 protocol 2 行为。
- 增加输入、快捷键、文件、扫码的消息类型。
- 增加电脑应用目录消息，手机只携带白名单 ID，Windows 端校验本地路径后启动。
- 为大文件建立独立认证 TCP 数据连接，禁止文件传输阻塞音频/控制连接。
- 统一 requestId、sequence、transferId、取消、超时和 ACK 语义。
- 连接断开时释放 Windows 注入的鼠标/键盘状态，取消手机相机和文件任务。
- 输入、摄像头、文件访问均须经过用户授权；只允许当前控制设备操作。

#### 阶段 B：Windows 端

- `InputBridgeService`：将规范化指针事件转换为 `SendInput` 鼠标事件。
- `ShortcutService`：执行白名单按键组合，提供防抖、超时和强制释放。
- `FileTransferService`：接收文件、校验、断点续传、目标目录配置、队列和速度统计。
- `ScanResultService`：校验 URL，仅对 `http/https` 默认浏览器打开；其他内容显示/复制。
- 增加极暗主题对应的 Windows 状态和传输面板。

#### 阶段 C：Android 端

- `TouchpadActivity/TouchpadView`：触摸板、手势和快捷键分区。
- 设备互联页可选择 `.exe` 并保存为应用白名单，连接后自动同步到手机。
- 自定义应用内分屏文件面板；支持已授权目录、Photo Picker 和传输托盘。
- 使用 CameraX + ML Kit 实时扫码和相册图片扫码。
- 使用 CameraX ImageCapture 内存结果发送照片；视频先提供实验开关。
- 使用独立的文件数据连接流式读取 URI，禁止 Base64 和整文件读入内存。
- 从后台收到电脑请求时，通过通知让用户确认后打开扫码/文件选择界面。

### v1.2.4.0 不包含

- Windows 系统虚拟摄像头设备。
- 真正关屏后的触摸输入。
- 未经用户授权的全盘文件浏览。
- 不受限制的宏录制或后台自动执行危险 URI。
- Windows→Android 主动文件发送（接收端协议已预留，排入后续小版本）。

### 验收标准

- 旧版 protocol 2 仍能正常连接和使用麦克风。
- protocol 3 双端能协商能力，任意一侧拒绝后功能按钮正确禁用。
- 触摸板连续移动、点击、拖动、滚动无残留按键；断线后所有按键释放。
- 快捷键重复点击不会产生重复或卡住的键位。
- 手机→Windows 文件传输不造成音频卡顿；支持大文件、取消、重试和 SHA-256 校验。
- 文件拖入触摸板共享区时不会误发鼠标事件。
- 实时摄像头和相册图片都能识别二维码；相册扫码默认只发送结果不发送原图。
- URL 打开前显示域名和确认界面。
- 极暗主题不调用系统亮度 API，背景为纯黑。
- Android 前台、退到桌面、锁屏、网络抖动和重复点击场景均有明确状态。

## 后续版本

- `v1.2.4.8`：Touch Bar 控制面板
  - Android 端在触摸板顶部增加可收起的横向 Touch Bar，默认常驻音量、亮度、播放控制、连接状态和当前应用。
  - Windows 端通过 protocol 3 推送应用标题、活动窗口、媒体会话、音量/亮度能力和标签页摘要；手机只渲染已授权字段。
  - 支持自定义卡片：启动已保存应用、发送快捷键、切换窗口、静音和预设音量。每个动作使用 `requestId` + ACK + 防抖，不能阻塞触摸板帧。
  - 标签页读取分为两级：优先接入浏览器扩展/本地伴侣 API；没有扩展时只显示活动窗口，避免以不安全方式读取浏览器内容。
  - 可行性：高。音量、媒体键、应用启动和活动窗口可直接复用现有 Windows 服务；亮度按显示器能力分级支持；浏览器标签页需要扩展或用户授权，不能承诺对所有浏览器免配置。
  - 参考实现：[Devdas-gupta/linkpad](https://github.com/Devdas-gupta/linkpad) 的媒体控制/快捷入口，以及 [Tygb99/phonepad](https://github.com/Tygb99/phonepad) 的多页面控制器设计。

- `v1.2.4.9`：Android 平板数位板
  - Android 端采集 `MotionEvent` 的坐标、压力、倾斜角、工具类型、悬停和按键状态，使用独立高优先级笔输入通道发送；触摸板和笔通道分离。
  - Windows 端第一阶段输出标准化笔事件并映射到 Windows Ink；第二阶段再评估虚拟 HID/Virtual Pen 设备，使 Krita、Photoshop 等应用获得更完整的压感支持。
  - 支持 USB 优先、局域网回退；坐标映射提供全屏、窗口和自定义工作区，加入校准、边缘补偿、丢帧序号和断线释放笔尖状态。
  - 可行性：中等偏高，但依赖平板和触控笔硬件是否提供压力/倾斜/悬停数据。普通手机电容笔只能实现低精度触摸笔，无法凭软件制造真实压感。
  - 参考实现：[solo-tk/flinktab](https://github.com/solo-tk/flinktab)（Android→Windows 低延迟数位板）、[zca60/tablet-pen-lab](https://github.com/zca60/tablet-pen-lab)（Windows Ink 笔输入）和 [lemonxah/drawing_tablet](https://github.com/lemonxah/drawing_tablet)（压感/倾斜数据链路）。

- 两个版本的共同约束：Touch Bar 与笔输入都使用独立功能通道，不修改已稳定的音频链路和触摸板连续移动链路；没有能力协商或用户授权时，手机端隐藏对应卡片。

- `v1.2.5.0`：Windows Media Foundation 虚拟摄像头，供 OBS/会议软件调用。
- 后续版本：更复杂的宏编辑、跨网络传输、文件夹同步和多设备协同。
