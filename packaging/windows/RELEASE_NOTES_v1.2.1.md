# VoiceSpreader v1.2.1

## 主要变化

- 设备互联服务支持多台 Android 手机和平板同时保持独立连接。
- 多台移动设备可以同时连接，但手机麦克风改为单设备独占路由；切换来源时旧设备会先停止录音并释放系统麦克风。
- 当前手机的音频包直接进入原生 WASAPI 自适应缓冲并写入 VB-CABLE，移除托管层二次拆包和多路混音，改善 Wi-Fi 录音卡顿。
- Windows 声音可选择发送到一台或多台移动设备；各连接使用独立有界缓冲，慢设备不会阻塞其他设备。
- 每台设备拥有稳定 ID，扬声器选择和麦克风增益会在重连后恢复；麦克风启用状态按当前会话重新确认。
- 手机作为校准麦克风时统一通过 VB-CABLE 暴露，在同步控制中选择 `CABLE Output`，不再维护重复的远程测量基准选项。
- 设备互联页重做为“已连接设备 / 添加设备 / 音频路由”布局，实时显示电平、缓冲和时钟漂移。
- 无设备时使用居中的空状态，右上角设备计数徽标保持固定高度并垂直居中。
- 同步控制页的左右区块底部对齐，输出数量较少时优先完整显示同步控制区域。
- 优化相对补偿自动值的字号和对比度。
- 全局延迟支持鼠标悬停滚轮调整：每格 `1 ms`，按住 `Ctrl` 时每格 `10 ms`。
- 校准失败后重新校准成功或取消时，会清除旧的校准警告，同时保留期间出现的其他独立错误。
- 音频路由切换增加互斥与取消保护，连续点击或设备中途断开不再留下半开启链路。
- 设置保存采用最新修订优先策略，快速连续调整时不会被较早的异步写入覆盖。
- 设备控制命令按设备串行处理并丢弃过期请求，改善快速勾选、取消和重连时的状态一致性。
- 手机端“启用麦克风”改为向 Windows 请求完整路由，Windows 建立 VB-CABLE 输出后再确认启动采集。
- Windows 设备麦克风开关现在直接控制实际路由，并与 Android 端的实际采集状态双向同步。
- 重复启停命令会重新确认实际状态；启动失败、请求超时或非当前设备擅自回传时会自动回退并关闭开关。
- 麦克风启用状态不再跨设备重连恢复，避免连接后出现开关已开但音频链路未建立的假状态。
- 手机端反向启停使用独立的请求帧；实际采集状态帧只更新状态，不再被当成新的路由命令，避免停止时两端互相回写造成快速抖动。
- 手机请求会写入运行记录；Windows 路由建立前仍会丢弃 PCM，避免未确认设备直接写入虚拟线缆。
- 手机主动关闭麦克风时立即撤销活动会话，并强制停止 VB-CABLE 输出；即使界面状态已经提前刷新也不会跳过底层关闭。

## 兼容性

- 本次 Windows 包内部修订号为 `1.2.1.7`，可覆盖更新早期的 `1.2.1.0` 至 `1.2.1.6` 测试包。
- Windows 客户端仍接受 v1 协议连接，但多设备稳定识别和 Windows 声音下行需要 Android v1.2.1。
- 手机麦克风写入第三方录音软件仍依赖用户自行安装 VB-CABLE。
- 音频协议当前适用于可信局域网，尚未提供端到端加密。
